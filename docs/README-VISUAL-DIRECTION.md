# README Visual Direction

The README should function as a premium product introduction before it becomes a technical manual.

## Above the fold

- Strong brand lockup
- One-line product promise
- Compact technology/status signals
- One primary visual story
- Immediate path to product, architecture and setup

## Visual assets

Future README iterations may use repository-hosted SVG/WebP assets for:

- product hero
- admissions journey
- architecture map
- family experience
- SIS vision

Assets should be purpose-built for the project, optimized for GitHub rendering, and never decorative stock imagery.

## Content rhythm

Hero → product promise → visual story → capabilities → architecture → security → development → roadmap → vision.

Avoid long walls of text. Use short editorial paragraphs, diagrams only when they explain relationships, and tables only when comparison is genuinely useful.

## Brand rule

The README must feel unmistakably Sammena before a reader reaches the first code block.
